# 浏览器架构

## 进程和线程

1. 线程：
   - 多线程就是并行处理任务
   - 线程不能单独存在，它是由进程来启动和管理的，进程中任一线程出错会导致整个进程崩溃
   - 线程之间可以对进程的公共数据进行读写操作
2. 进程：
   - 进程就是一个程序的运行实例
   - 启动一个程序的时候，操作系统会为该程序创建一块内存，用来存放代码、运行中的数据、一个执行任务的主线程，这样的一个运行环境叫进程
   - 一个进程关闭后，操作系统会回收进程所占用的内存
   - 进程之间相互隔离，所以一个进程崩溃了不会影响到其他进程

### 单进程浏览器

![单进程浏览器](/browser/6ddad2419b049b0eb2a8036f3dfff1ca.webp)

早期的浏览器所有模块运行在同一个进程，这就会导致浏览器不稳定、不流畅、不安全

不稳定：任意一个线程崩溃就会导致整个浏览器的崩溃

不流畅：单进程会导致内存泄漏问题；js执行环境和浏览器插件都在同一个线程中，执行会回造成堵塞

不安全：浏览器插件和js脚本都可以通过浏览器的漏洞来获取系统权限，对电脑做一些不安全的操作

### 早期多进程浏览器

![多进程浏览器](/browser/cdc9215e6c6377fc965b7fac8c3ec960.webp)

除了浏览器主进程，页面是单独的渲染进程（排版引擎Blink和js引擎V8），插件也运行在单独的插件进程（负责插件运行）之中，进程间通过IPC机制进程通信

解决不稳定：进程间相互隔离，所以某个页面或者某个插件崩溃，只影响当前页面或插件的进程，不影响主进程和其他页面的进程

解决不流畅：js脚本和插件是单独进程，不会阻塞主进程和其他页面进程；关闭一个页面会回收所占用的内存不会导致浏览器的内存泄漏

解决不安全：插件进程和渲染进程运行在沙箱中，不能读写硬盘的数据、不能获取操作系统权限


### 后来的多进程浏览器

![多进程浏览器](/browser/b61cab529fa31301bde290813b4587fc.webp)

后来又把网络进程（网络资源加载）、GPU进程（UI界面绘制）从浏览器主进程独立了出来

打开一个浏览器，会最少有4个进程：浏览器主进程、网络进程、渲染进程、GPU进程，有可能还有插件进程

打开多个页面会有多个渲染进程，但是如果是同一个站点则共享渲染进程


### 面向服务的架构（SOA）

![SOA](/browser/329658fe821252db47b0964037a1de2a.webp)

最近的Chrome浏览器，各种模块会被重构成独立的服务，每个服务都可以在独立的进程中运行（单独的进程号），访问服务必须使用定义好的接口，通过IPC来通信，从而构建一个更内聚、松耦合、易于维护和扩展的系统

这些基础服务类似于操作系统的底层服务
