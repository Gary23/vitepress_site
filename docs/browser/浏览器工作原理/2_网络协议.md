# 网络协议

## TCP/IP协议

不管是HTTP还是WebSocket，都是基于TCP/IP协议的

### 一个数据包的传输

互联网中文件会被拆分为很多小的数据包来传输

![案例](/browser/943ac29f7d5b45a8861b0cde5da99032.webp)

**数据是如何被完整地送达应用程序**
   - 数据包传输要符合IP协议标准（网络层）
   - A主机中，数据包在传输层附加TCP头（端口号、数据包序列号），组成新的TCP数据包，再交给网络层
   - 网络层附加IP头（IP地址等信息）到TCP数据包上，组成新的IP数据包，交给底层
   - B主机接收到数据包，在网络层拆开IP头信息，交给传输层
   - 传输层把TCP头拆开，根据端口号，把数据交给上层应用程序

**TCP和UDP**

在数据传输中，UDP和TCP的流程是一致的，都是**在传输层把数据送达应用程序**，它们不同点事：
   - 对于数据包丢失情况，UDP没有重发机制，TCP有重发机制，TCP更可靠
   - 对于数据包完整性，UDP如果乱序了则不知道如何组合数据包还原完整文件，TCP有数据包排序机制可以把乱序数据包组合成一个完整文件
   - 对于传输速度，UDP传输速度比TCP更快
   - 所以UDP适合对数据完整性要求不严格的领域，比如视频、互动游戏；TCP适合对数据可靠性要求高的应用，比如邮件



![案例2](/browser/440ee50de56edc27c6b3c992b3a25844.webp)

**一个完整的TCP连接的生命周期包**
   - 建立连接阶段：通过三次握手建立客户端和服务器之间的连接。在数据包传输前先做好两段准备工作，三次握手就是建立一个TCP连接时，总共要发送三个数据包以确认连接的建立
   - 传输数据阶段：接收端需要对每个数据包进行确认操作，也就是需要发送确认数据包给发送端。如果发送端没有收到确认数据则视为丢包，触发重发机制。数据包都到达接收端后会按照TCP头的序号进行排序，组成完整的数据
   - 断开连接阶段：数据传输完毕之后，就要终止连接了，用四次挥手保证双方都能断开连接

TCP为了保证数据传输的可靠性，牺牲了数据包的传输速度，因为“三次握手”和“数据包校验机制”等把传输过程中的数据包的数量提高了一倍。

## HTTP 协议

HTTP协议（应用层）是建立在TCP（传输层）连接的基础之上，**HTTP是一种允许浏览器向服务器获取资源的协议，是Web的基础**

![HTTP请求](/browser/1b49976aca2c700883d48d927f48986c.webp)

**浏览器发起HTTP请求流程**

1. 构建请求
2. 查找缓存
   - 浏览器中查找是否有缓存，如果已有缓存就会拦截请求并结束，返回缓存的资源
3. 准备IP地址和端口
   - 通过DNS（域名系统）找到网站域名的映射ip地址。
   - 拿到IP之后就需要获取端口号，通常情况是url没有明确知名则默认80
4. 等待TCP队列
   - Chrome有个机制，同一个域名最多只能建立6个TCP连接，多余的请求会进入排队等待状态
5. 建立TCP连接
   - 和服务器进行TCP连接（三次握手）
6. 发送HTTP请求
   - 发送HTTP数据给服务器，首先向服务器发送请求行（请求方式、请求URI、HTTP协议版本），告诉服务器请求方式、需要什么资源或数据
   - 发送完请求行之后，还要以请求头形式发送其他一些信息（浏览器信息、cookie信息等）

**服务器端处理HTTP请求流程**

1. 返回请求
   - 服务器返回数据给浏览器，可以使用命令查看`curl -i  https://www.baidu.com/`
   - 服务器首先会返回响应行（协议版本和状态码）
   - 随后服务器会返回响应头（服务器信息、返回数据类型、服务器要在客户端保存的cookie信息）
   - 响应头之后返回响应体，包括资源或数据
2. 断开连接
   - 一旦服务器向客户端返回了请求数据，它就要关闭TCP连接
   - 如果浏览器或者服务器头信息中加入了`Connection:Keep-Alive `，可以继续通过这个TCP连接发送数据，保持连接可以省去下次请求时要建立的时间
3. 重定向
   - 响应行返回状态码301就是告诉浏览器要重定向到另一个网址，网址包含在响应头的Location字段中

::: info 第一次打开站点速度更快

因为第一次加载页面过程中，缓存了一些耗时数据

比如DNS缓存和页面资源缓存，其中页面缓存是通过响应头的`Cache-Control`字段设置一个缓存时间，如果缓存过期，请求头会增加一个`If-None-Match`字段，服务端收到后，如果请求的资源没有没有更新就返回304，如果更新了就返回最新的资源

::: info 登陆状态如何保持

登陆信息用POST方法提交到服务器，服务器验证后会生成一段标识用户身份的字符串，把字符串写到响应头Set-Cookie字段里

浏览器会把这个字段的信息保存本地，当浏览器再次发起HTTP请求时，浏览器会把Cookie通过请求头发给服务器

服务器接收请求头的Cookie之后,当查到包含用户身份的字符串时就查询后台并判断该用户的登陆状态

:::
