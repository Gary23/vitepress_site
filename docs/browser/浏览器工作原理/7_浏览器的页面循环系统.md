# 浏览器的页面循环系统

## 事件循环和消息队列

1. 消息队列是一种数据结构，可以存放要执行的任务，消息队列是"先进先出"的

2. 渲染主线程从消息队列头部中读取任务并执行，其他线程添加新任务进消息队列尾部

3. 通过消息队列实现了线程之间的通信

4. 渲染进程的IO线程可以接受其他进程的消息，然后添加到时间队列中

5. 消息队列任务的类型包含输入事件、微任务、文件读写、WebSocket、JavaScript、页面相关事件（JavaScript执行、解析DOM、样式计算、布局计算、CSS动画等）

6. 通过"性能"页签，可以看到浏览器的事件执行流程

7. 消息队列的任务也称为宏任务，当遇到高优先级的任务（比如DOM变化），会放到当前宏任务下的微任务中，当前宏任务的主要功能完成后，先执行宏任务中的微任务

## 延迟队列

1. 除了正常的消息队列外，还有一个特殊的消息队列，用来执行定时器的延迟任务，渲染进程会将定时器的回调任务添加到这个队列中。

2. 调用setTimeout时，渲染进程会创建一个回调任务，包含了回调函数、当前发起时间、延迟时间

3. 即便延迟时间设置为0，也需要等待当前任务执行完成后，才能执行回调，可能会延长定时时间

4. 即便延迟时间设置为0，如果在定时器函数内嵌套定时器，那么系统会设置最短时间间隔为4毫秒，可能会延长定时时间，所以实时性较高的动画就不适合用setTimeout实现

5. 即便延迟时间设置为0，未被激活的页面中定时器最小的时间间隔是1000毫秒

## 消息队列的宏任务和微任务

1. 在消息队列和延迟队列中的任务都是宏任务，宏任务时间间隔不能精确控制，延迟队列也容易受到其他宏任务的影响导致时间不精确，不适合对实时性要求特别高的任务

2. 微任务是需要异步执行的函数，执行时机在主函数执行结束后、宏任务结束之前执行，产生微任务有两种方式：MutationObserver和Promise，所以只要DOM节点变化或者使用Promise，就会产生微任务

## 生成器和协成

1. 生成器是一个带星号函数，可以暂停执行和恢复执行，生成器函数内部遇到yield关键字会暂停并返回关键字后面的内容给外部，外部通过next方法恢复函数的执行

2. 协成是一种比线程更加轻量级的存在，可以看做是跑在线程上的任务，一个线程可以有多个协程但同时只能执行一个，协程的调度由js代码写的程序控制

```js
// 生成器函数
function* demo() {
  yield 1;     // yield暂停demo协程，切换协程到全局
  yield 2;
  return 3;    // return结束demo协程
}
console.log('0')
let genDemo = demo();   // 创建demo协程对象
console.log(genDemo.next().value);    // 由全局协程切换到demo协程
console.log(genDemo.next().value);
console.log(genDemo.next().value);
```

3. async/await就是生成器（Generator）和协成（Coroutine）的语法糖

4. async是一个异步执行+隐式返回promise的函数

```js
async function demo2() {
  return 1;
}
console.log(demo2.next());    // Promise {<resolved>: 1}
```

5. 当async函数执行到await的时候，会创建一个Promise对象，js会将该任务提交到微任务队列然后暂停当前协程，将promise对象和主线程的控制权转交给父协程，父协程通过调用promise.then来改变promise的状态，父协成在执行完宏任务结束前会检查微任务队列，执行promise.then()中的回调函数恢复async函数的协程
